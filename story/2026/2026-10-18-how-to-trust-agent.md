# 怎么信任 Agent

今年（2026 年）才只是以 Claude Code 为标志的 Coding Agent 第二年（Claude Code 发布于 2025 年 2 月 24 日），但是现在依然还没有特别多的人大量使用 Agent。
Coding Agent 已经从只负责 Coding 转向泛用 Agent 了，因为 Code 本身就是 Agent 与世界交互的主要方式。

<!-- more -->

发生明显变化的过程是

- 生成文本 -> 简单的补全、替换
- Tool call -> Agent 只能输出固定工具调用
- MCP -> 通过一定的协议来提供大量 Tool, 不管是不是用得上
- Code mode / DSL / Shell is all you need / Dynamic workflow -> 让 Agent 能以代码的方式来编排和操作一切，Agent 会逐步的去发现他环境的能力和它的世界做交互。

一路走过来，Agent 做的事情越来越多，人做的事情越来越少。但是对使用 Agent 尚且不足的人来说，门槛却变得越来越大了，AI Agent 未来会（或者说已经）变成接近手机、搜索引擎这种基础设施一样的存在。
我认为很难的一点是建立信任。

Agent 领域现在一个非常热门的话题是 Harness（挽具 / 缰绳），目的就是为了驾驭 Agent。

过去一年模型迭代极快，最近开始放缓，模型对于所有人来说都是平等的存在，那么每个人的不同点就在于对 Agent 不同的理解，你的 Agent 区别于别人，你使用 Agent 的效率和结果不同于别人，那么多半是 skill issue 了。

模型迭代，每次都会带来个人 Harness 的部分调整，那么选择投入个人时间精力的时候，强烈建议选择自己完全掌控的方式，以下是我个人掌控 Agent 的方式。

## 不变的是沉淀

> 下一次模型升级后，什么仍然属于你？

这是我认为在这个过程中比较有价值的问题，不过最近这个问题的价值在逐渐缩减了，因为模型已经内化了大部分你知道的好的 Prompt 实践经验了，但这个问题依然重要，它决定了你做哪些事才有价值。

- 会变化的东西
  - 模型、产品、Prompt 技巧
  - 昨天需要手工写出的步骤，明天可能成为模型的默认能力。
- 应该留下的东西
  - 上下文、判断、过程与证据
  - 它们不会因为模型变强就自动进入下一个模型。

问题不是“哪个 Agent 最强”，而是“哪些资产能跨越 Agent 的更替”。

所以，我会围绕留存价值来组织我的信息结构。

> Harness 有半衰期，Context 会复利

时常我们都会追新，尝试切换使用的工具，例如 Codex 出来的时候，从 CC 迁移到 Codex，DSH 出的时候又迁移到 DSH，结果又发现 Hermes 也不错。

Harness 时常会变，今天可能发现了这个插件好用，明天又听说了另一个，来回的变化切换是很正常的行为，甚至 Harness 本身也是在快速迭代增加新的功能和做出内部架构的变化。

但本地组织好的上下文、结构与信息，无论工具怎么切换，它们都不会失效。理论上，切换 Agent 带来的体验变化更多取决于产品品味；但能否完成任务、达成目标，核心取决于本地信息上下文的组织。

在本地上下文中，我们也需要随着模型升级迭代来优化本地的信息内容。

## 沉淀的是价值

> 信息越多，不等于掌控越多

在早期的时候，模型对指令的遵从，对常见使用模式的理解远远不如现在，但是现在模型已经是另外一个 Level 了，你需要相信它能完成预期的任务，建立这样信任需要很多的前提

> Confidence comes from inspectability, not familiarity.

- 应该能回答
  - 它基于哪些文件、命令和结果？
  - 哪些内容是事实，哪些是推断？
  - 哪些关键上下文可能缺失？

信任来自于对过程的肯定，来自于多次的沟通尝试，来自于历史的任务完成，更来自于我对过程的可审查。

> 不要只留下答案，要留下想法如何变成答案的路径。

因此，我本地组织的结构会尽量保留过程内容，某种程度上相当于是对它思维过程的“蒸馏”或概括。你可以选择不看，但是不能没有，因为下一次是否成功很可能依赖这一次过程：它可以犯错，但不能重复犯错；做成过的事，有记录就能再次做成。

> 好的静态规则，来自很多次动态判断。

这个过程好似一个漏斗，人类（或者 Agent）都是能做到吃一堑长一智的，通常规则也都会包含“启发式”的规则补充，且过程留存也应该是能辅助于提供和完善更多的规则，当这样的基础规则能循环起来后，逐步的优化迭代其实现在的 Agent 已然能够自行完成。

## 价值产生信任

当你和 Agent 沟通次数越来越多了以后，你会发现它能越来越贴合你的想法和预期。在这样的正向反馈循环下，才能对 Agent 产生足够的信任，理解它的边界和能力，然后在每次升级后，再次认识它，扩展新的能力和边界，长此以往才能做到驾驭 Agent。
